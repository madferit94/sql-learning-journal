## 게시 방식

- 2026-10-08 확인한 노션의 11일차·60문제를 포함했습니다.
- 한글 설명과 실패한 시도를 보존하면서 Markdown 서식을 정리했습니다. 노션 전용 태그·접근 불가능한 내부 파일 인용을 제거하고 HTML 표를 Markdown 표로 바꿨습니다.
- 영어는 모든 문제를 포함한 편집 번역이며 반복된 코칭 대화 전체의 직역은 아닙니다. 해석상 주의점도 덧붙였습니다. 상세 원기록은 한글판에서 확인할 수 있습니다.
- 마지막으로 기록된 SQL을 `sql/`에 추출했습니다. Day11 문제 3의 미해결 쿼리도 포함합니다. '최종 기록'은 검증 완료·정답 보증을 뜻하지 않습니다.
- Day06 고객 식별자는 일관되게 가명 처리했습니다. 원본 데이터·계정 정보·관계없는 로컬 파일은 포함하지 않았습니다.
- `query-manifest.json`은 날짜·문제 번호·원문 코드 블록 순서·SHA-256 값을 연결합니다. 게시 내용의 일관성을 확인하기 위한 것으로 DB 결과의 정확성을 증명하지 않습니다.

## 해석할 때 주의할 점

1. 주와 고객으로 묶은 한 행은 **주·고객 조합**입니다. 한 고객이 여러 주에 나타나면 주별 고객 수 합계는 전체 고유 고객 수와 다를 수 있습니다. 재구매 여부도 해당 주와 기간 안에서 계산됩니다.
2. 여기서 재구매율은 관찰 기간 내 2회 이상 주문한 고객의 비율입니다. 코호트 유지율·인과 효과·미래 충성도를 뜻하지 않습니다.
3. JOIN 전후 행 수가 같아도 미매칭과 중복 확대가 서로 상쇄될 수 있으므로 행 수만으로 정합성을 확정할 수 없습니다.
4. MySQL `ONLY_FULL_GROUP_BY` 적용은 그룹과 함수적 종속성(키가 다른 값을 결정하는 관계)에 따라 달라집니다. 팀 ID만 그룹화하고 팀명을 조회하는 쿼리는 적절한 유일성 제약이 필요하며, 이 저장소에는 해당 제약조건이 없습니다.
5. 잘못된 시도와 손상된 원문 코드 조각은 학습 이력으로 남겼습니다. '첫 시도'를 실행 가능한 정답으로 복사하지 마세요. `SUM(x)/COUNT(*)`와 `AVG(x)`가 같으려면 NULL 처리와 분모가 일치해야 합니다.
6. Day11 문제 3은 마지막 쿼리 뒤에도 ERROR 1064가 기록되어 있습니다. 원문은 특수 공백을 원인으로 추정하지만, 원인과 성공적인 수정 결과를 이번에 재현하지 않았습니다.

## 확인한 범위

한영 일차·문제 수, 내부 링크, 추출 쿼리 해시, 비공개 원본 내보내기 파일의 제외, Day06 식별자 대체를 점검했습니다. 쿼리를 다시 실행할 데이터베이스는 없었습니다. 기존 결과 표는 당시 기록이며 일부는 전체 결과의 발췌입니다.
