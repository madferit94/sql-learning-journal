### 2) 이번 학습 목표
오랜만에 SQL 학습을 다시 시작했기 때문에, 바로 JOIN/CASE WHEN/Window Function으로 넘어가기보다 **기본적인 쿼리를 빈 화면에서 직접 작성하는 감각을 복구**하는 것을 목표로 했다.
이번 세션의 학습 범위:
- `SELECT`, `FROM`, `WHERE`
- 비교 연산자
- `AND`, `OR`
- `ORDER BY`, `LIMIT`
- `COUNT()`, `AVG()`, `SUM()`
- `GROUP BY`
특히 SQL을 다음 흐름으로 이해하고 쿼리를 구성하는 데 집중했다.
`데이터 선택 → 조건 필터링 → 그룹화 → 집계 → 정렬`

## 3) 문제별 SQL 실습
### 문제 1. 특정 시즌 경기 조회
**문제**
`Match` 테이블에서 **2015/2016 시즌 경기만 조회**한다.
출력 컬럼: `season`, `date`, `home_team_goal`, `away_team_goal`
10개 행만 확인한다.
**SQL**
```sql
SELECT season, date, home_team_goal, away_team_goal
FROM `Match`
WHERE season = '2015/2016'
LIMIT 10;
```
**실제 결과 **


| season | date | home_team_goal | away_team_goal |
| --- | --- | --- | --- |
| 2015/2016 | 2015-07-24 00:00:00 | 2 | 1 |
| 2015/2016 | 2015-07-25 00:00:00 | 2 | 1 |
| 2015/2016 | 2015-07-25 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-07-25 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-07-25 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-07-26 00:00:00 | 1 | 1 |
| 2015/2016 | 2015-07-26 00:00:00 | 3 | 2 |
| 2015/2016 | 2015-07-26 00:00:00 | 2 | 1 |
| 2015/2016 | 2015-10-04 00:00:00 | 1 | 1 |
| 2015/2016 | 2015-10-04 00:00:00 | 4 | 1 |


**핵심 학습 내용**
`WHERE`는 특정 조건을 만족하는 행만 필터링한다. 또한 `season = '2015/2016'`처럼 \*\*문자열 조건은 작은따옴표(’ ’)\*\*로 감싸서 비교한다.

### 문제 3. AND를 활용한 복수 조건
**문제**
**2015/2016 시즌이면서 홈팀이 3골 이상 기록한 경기**를 조회한다.
**SQL**
```sql
SELECT season, date, home_team_goal, away_team_goal
FROM `Match`
WHERE season = '2015/2016'
  AND home_team_goal >= 3
LIMIT 10;
```
**실제 결과 **


| season | date | home_team_goal | away_team_goal |
| --- | --- | --- | --- |
| 2015/2016 | 2015-07-25 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-07-25 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-07-25 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-07-26 00:00:00 | 3 | 2 |
| 2015/2016 | 2015-10-04 00:00:00 | 4 | 1 |
| 2015/2016 | 2015-10-04 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-10-03 00:00:00 | 3 | 0 |
| 2015/2016 | 2015-10-17 00:00:00 | 3 | 0 |
| 2015/2016 | 2015-10-25 00:00:00 | 3 | 1 |
| 2015/2016 | 2015-10-24 00:00:00 | 3 | 4 |


**핵심 학습 내용**
`AND`는 **두 조건을 모두 만족하는 행만** 남긴다. 따라서 시즌 조건과 득점 조건을 함께 걸어 필터 범위를 더 좁혔다.

### 문제 4. OR 조건 활용
**문제**
홈팀 또는 원정팀 중 **한 팀이라도 4골 이상 기록한 경기**를 조회한다.
**SQL**
```sql
SELECT date, home_team_goal, away_team_goal
FROM `Match`
WHERE home_team_goal >= 4
   OR away_team_goal >= 4
LIMIT 10;
```
**실제 결과 **


| date | home_team_goal | away_team_goal |
| --- | --- | --- |
| 2008-08-17 00:00:00 | 5 | 0 |
| 2008-11-01 00:00:00 | 4 | 1 |
| 2008-11-29 00:00:00 | 4 | 2 |
| 2008-11-29 00:00:00 | 4 | 0 |
| 2008-12-06 00:00:00 | 5 | 1 |
| 2008-12-06 00:00:00 | 5 | 2 |
| 2008-12-14 00:00:00 | 1 | 4 |
| 2008-12-20 00:00:00 | 4 | 3 |
| 2008-12-20 00:00:00 | 5 | 1 |
| 2009-01-18 00:00:00 | 4 | 1 |


**핵심 학습 내용**
`OR`는 여러 조건 중 **하나 이상**을 만족하면 해당 행을 선택한다. “홈/원정 중 어느 한쪽이라도 고득점” 같은 질문은 `OR`로 표현할 수 있다.

### 문제 5. WHERE 이후 ORDER BY 정렬
**문제**
홈팀이 3골 이상 기록한 경기만 선택한 뒤, **홈팀 득점이 높은 경기부터** 조회한다.
**SQL**
```sql
SELECT date, home_team_goal, away_team_goal
FROM `Match`
WHERE home_team_goal >= 3
ORDER BY home_team_goal DESC
LIMIT 10;
```
**실제 결과 **


| date | home_team_goal | away_team_goal |
| --- | --- | --- |
| 2010-10-24 00:00:00 | 10 | 0 |
| 2015-12-20 00:00:00 | 10 | 2 |
| 2009-11-22 00:00:00 | 9 | 1 |
| 2013-03-30 00:00:00 | 9 | 2 |
| 2010-11-06 00:00:00 | 9 | 0 |
| 2015-04-05 00:00:00 | 9 | 1 |
| 2010-05-09 00:00:00 | 8 | 0 |
| 2011-08-28 00:00:00 | 8 | 2 |
| 2012-12-23 00:00:00 | 8 | 0 |
| 2014-10-18 00:00:00 | 8 | 0 |


**핵심 학습 내용**
먼저 `WHERE`로 대상 행을 제한하고, 그 결과를 `ORDER BY home_team_goal DESC`로 **높은 값부터 내림차순 정렬**한다.

### 문제 6. 특정 시즌 전체 경기 수 계산
**문제**
2015/2016 시즌의 전체 경기 수를 계산한다.
**SQL**
```sql
SELECT COUNT(*) AS match_count
FROM `Match`
WHERE season = '2015/2016';
```
**실제 결과 **


| match_count |
| --- |
| 3326 |


**핵심 학습 내용**
`WHERE`로 2015/2016 시즌만 남긴 뒤, `COUNT(*)`가 \*\*남은 행의 개수(경기 수)\*\*를 계산한다.
---
### 문제 7. 시즌별 경기 수 계산
**문제**
전체 경기 데이터를 **시즌별로 그룹화하여 시즌별 경기 수**를 계산한다.
**SQL**
```sql
SELECT season, COUNT(*) AS match_count
FROM `Match`
GROUP BY season;
```
**실제 결과 **


| season | match_count |
| --- | --- |
| 2008/2009 | 3326 |
| 2009/2010 | 3230 |
| 2010/2011 | 3260 |
| 2011/2012 | 3220 |
| 2012/2013 | 3260 |
| 2013/2014 | 3032 |
| 2014/2015 | 3325 |
| 2015/2016 | 3326 |


**핵심 학습 내용**
`GROUP BY season`이 동일한 시즌의 경기들을 하나의 그룹으로 묶고, `COUNT(*)`가 \*\*각 그룹의 행 수(경기 수)\*\*를 계산한다.
추가 검증:
- 8개 시즌의 경기 수를 모두 합하면 **25,979경기**이며 이는 `Match` 테이블의 전체 행 수와 일치한다.
---
### 문제 8. WHERE와 GROUP BY 함께 사용
**문제**
**2012/2013 시즌 이후 데이터만 선택한 뒤 시즌별 경기 수**를 계산한다.
**SQL**
```sql
SELECT season, COUNT(*) AS match_count
FROM `Match`
WHERE season >= '2012/2013'
GROUP BY season
ORDER BY season ASC;
```
**실제 결과 **


| season | match_count |
| --- | --- |
| 2012/2013 | 3260 |
| 2013/2014 | 3032 |
| 2014/2015 | 3325 |
| 2015/2016 | 3326 |


**핵심 학습 내용**
먼저 `WHERE`가 분석 대상 행(시즌 범위)을 제한하고, 그 결과를 `GROUP BY`가 시즌별로 그룹화해 집계를 수행한다. 또한 이 데이터의 `season` 값이 모두 `YYYY/YYYY` 형식으로 동일하게 저장되어 있어, **문자열 비교로 시즌 필터링**이 가능했다.

### 문제 9. 시즌별 평균 홈 득점
**문제**
각 시즌의 **평균 홈팀 득점**을 계산한다.
**SQL**
```sql
SELECT season, AVG(home_team_goal) AS avg_home_goals
FROM `Match`
GROUP BY season
ORDER BY season ASC;
```
**실제 결과 **


| season | avg_home_goals |
| --- | --- |
| 2008/2009 | 1.50541190619363 |
| 2009/2010 | 1.54117647058824 |
| 2010/2011 | 1.54846625766871 |
| 2011/2012 | 1.57267080745342 |
| 2012/2013 | 1.552 |
| 2013/2014 | 1.57882585751979 |
| 2014/2015 | 1.5203007518797 |
| 2015/2016 | 1.54389657245941 |


**핵심 학습 내용**
`AVG(home_team_goal)`은 각 시즌 그룹 안에서 홈 득점의 평균을 계산한다.
학습 과정에서 초기에 아래처럼 불필요한 `WHERE` 조건을 작성한 적이 있었다.
```sql
WHERE season = home_team_goal
```
하지만 이 문제는 특정 시즌/특정 경기만 필터링하는 문제가 아니라, 전체 데이터를 시즌별로 그룹화해 평균을 계산하는 문제이므로 `WHERE`가 필요하지 않았다. 즉, SQL을 작성할 때 `WHERE`를 습관적으로 넣기보다 **분석 질문에 실제 필터링 조건이 있는지 먼저 판단해야 한다**는 점을 다시 확인했다.

### 문제 10. 시즌별 홈팀 총 득점
**문제**
각 시즌의 **홈팀 총 득점**을 계산한다.
**SQL**
```sql
SELECT season, SUM(home_team_goal) AS total_home_goals
FROM `Match`
GROUP BY season
ORDER BY season ASC;
```
**실제 결과 **


| season | total_home_goals |
| --- | --- |
| 2008/2009 | 5007 |
| 2009/2010 | 4978 |
| 2010/2011 | 5048 |
| 2011/2012 | 5064 |
| 2012/2013 | 5053 |
| 2013/2014 | 4787 |
| 2014/2015 | 5055 |
| 2015/2016 | 5135 |


**핵심 학습 내용**
`SUM(home_team_goal)`은 시즌별 홈 득점의 합계를 계산한다.
추가 검증 사례(결과 간 논리 일치 확인):
- 2008/2009 시즌
- 경기 수: 3,326
- 홈 총 득점: 5,007

## 4) 이번 세션에서 복기한 SQL 핵심 (표 정리)


| 개념 | 역할(요약) | 예시 |
| --- | --- | --- |
| `WHERE` | 집계/그룹화 전에 조건을 만족하는 행만 남김 | `WHERE season = '2015/2016'` |
| `AND` | 두 조건을 모두 만족해야 함 | `WHERE season = '2015/2016' AND home_team_goal >= 3` |
| `OR` | 조건 중 하나 이상 만족하면 됨 | `WHERE home_team_goal >= 4 OR away_team_goal >= 4` |
| `COUNT()` | 행의 개수를 계산 | `COUNT(*)` |
| `GROUP BY` | 동일 값을 가진 행을 그룹으로 묶음 | `GROUP BY season` |
| `AVG()` | 그룹 내 값의 평균 계산 | `AVG(home_team_goal)` |
| `SUM()` | 그룹 내 값의 합 계산 | `SUM(home_team_goal)` |
| `ORDER BY` | 결과를 특정 기준으로 정렬 | `ORDER BY home_team_goal DESC` |

## 5) 이번 세션에서 다시 확인한 SQL 사고 순서
문법을 개별적으로 외우기보다, **분석 질문을 SQL 구조로 변환**하는 순서로 정리했다.
1. 무엇을 출력해야 하는가? → `SELECT`
2. 어느 테이블을 사용하는가? → `FROM`
3. 특정 데이터만 필요한가? → `WHERE`
4. 어떤 기준으로 묶어야 하는가? → `GROUP BY`
5. 무엇을 계산해야 하는가? → `COUNT / AVG / SUM`
6. 어떤 순서로 보여줘야 하는가? → `ORDER BY`
7. 일부 결과만 확인할 것인가? → `LIMIT`
특히 이번 학습에서 중요했던 점은 **WHERE가 항상 필요한 것이 아니라는 점**이다.
- “2015/2016 시즌 평균 홈 득점” → 시즌 필터가 필요하므로 `WHERE`가 필요
- “시즌별 평균 홈 득점” → 전체 데이터를 시즌별로 나누는 문제이므로 별도의 `WHERE` 없이 `GROUP BY` 중심으로 해결

## 6) 간단한 학습 회고
오랜만에 SQL을 다시 시작하면서 처음부터 고급 문법으로 넘어가기보다, `Match` 단일 테이블을 이용해 기본적인 데이터 조회와 필터링부터 다시 복습했다. 초반에는 `WHERE` 뒤에 비교할 컬럼을 빠뜨리거나, 필요하지 않은 `WHERE` 조건을 넣는 실수가 있었지만 문제를 반복하면서 `SELECT → FROM → WHERE` 구조와 `GROUP BY`를 이용한 집계 구조를 다시 확인했다.
특히 단순히 문법을 암기하는 것보다 **“이 분석 질문에서 필터가 필요한지, 그룹화가 필요한지, 어떤 집계 함수를 사용해야 하는지”를 먼저 판단하는 과정**이 중요하다는 점을 다시 확인했다.
---
## 오늘의 핵심 정리
- 기본 쿼리에서 가장 자주 쓰는 뼈대는 `SELECT → FROM → (WHERE) → (GROUP BY) → (집계함수) → (ORDER BY) → (LIMIT)` 흐름으로 정리할 수 있었다.
- `WHERE`는 “무조건 넣는 절”이 아니라, **질문에 필터 조건이 있을 때만** 사용하는 것이 자연스럽다.
- `COUNT / AVG / SUM` 결과는 서로 연결해서 검증할 수 있고(예: `SUM ÷ COUNT ≈ AVG`), 실제 데이터 결과를 가지고 논리 일치 여부를 확인하는 과정이 유용했다.

## 다음 학습 계획
다음 SQL 학습은 **문제 11부터 이어서 진행**한다.
학습 순서:
`WHERE + GROUP BY 복합 문제`
→ `HAVING`
→ `JOIN 복습`
→ `CASE WHEN`
→ `Window Function`
Window Function에서는 향후 아래 내용을 학습할 예정이다.
- `ROW_NUMBER()`
- `RANK()`
- `DENSE_RANK()`
- `PARTITION BY`
- `LAG()`
- `SUM() OVER()`
최종 목표는 SQL 문법을 단순 암기하는 것이 아니라, 데이터 분석 질문을 보고 필요한 SQL 구조를 스스로 선택해 작성하고 결과를 검증할 수 있는 형태로 학습을 이어가는 것이다.
