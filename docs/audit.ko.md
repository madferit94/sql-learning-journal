### 점검 범위

Day1\~22의 최종 쿼리 115개를 MySQL 8.4.11·ONLY_FULL_GROUP_BY 활성화 환경에서 재실행했고 모두 정상 실행됐습니다. 이 결과는 문법 실행과 명시한 데이터 범위의 검증이며 모든 분석 해석이나 과거 실행 시점을 보증하지 않습니다. 과거 실행 시간은 새 실행 시간으로 덮지 않았습니다.

### 재실행 환경

- Day1\~3: 과거 Match·date를 현재 matches·match_date에 대응했습니다. 과거 오류 원문은 SQLite 계열 형식과 부합하지만 당시 전체 실행 환경을 확정하지 않습니다.
- Day4\~5·9\~11: 삭제 전 Olist 백업을 별도 임시 검증 DB로 복원했습니다. 고객·주문 연결 키와 JOIN 행 수를 확인했습니다. 기존 학습 DB는 덮어쓰지 않았고 임시 DB는 점검 후 제거했습니다.
- Day14\~15·20: 바쿠 11377만 노출하는 별도 조회 환경입니다. Day21은 오스틴까지 18경기, Day22는 명시된 문제 범위에 따라 멕시코까지 19경기 또는 오스틴 한 경기입니다.
- 금융·이커머스: 현재 finance·retail_study를 읽기 전용으로 조회했습니다. 금융 금액의 통화는 확인되지 않았습니다.

### 기록을 해석하는 기준

- 과거 시도에 오답이 남아 있는 것은 학습 기록이며 최종 답안과 구분합니다.
- 과거 출력 표의 빈칸·축약 표기·일부 행은 전체 DB의 NULL이나 누락으로 단정하지 않습니다.
- ORDER BY가 없거나 동점 해소 기준이 부족한 LIMIT 조회는 행 선택·순서가 달라질 수 있습니다.
- 이름별 집계와 ID별 집계, 반올림 후 표시와 원래 값 계산을 구분합니다.
- CASE의 ELSE 생략은 목적에 따라 올바릅니다. 결측 금액·득점을 무조건 0이나 무승부로 채우지 않습니다.



### 과거 출력과 현재 검증의 차이

과거 출력은 덮어쓰지 않습니다. 날짜에 시간 부분이 생략되거나 팀 이름이 축약된 표, 빈 날짜 셀, 정렬 동률의 LIMIT 경계는 현재 전체 출력과 문자 단위로 같지 않을 수 있습니다. 이런 표현 차이와 수치 오류를 구분했습니다. Day1 문제 9의 1.552는 실제 수치 오기로 정정했습니다.

### 재현 한계

공개 저장소는 데이터·백업·임시 DB를 포함하지 않습니다. Day1~3은 테이블·날짜 컬럼 이름을 대응했고, Olist은 비공개 로컬 백업을 격리 복원했으며, F1은 기록된 경기 범위만 노출하는 임시 뷰를 사용했습니다. 따라서 SQL 파일을 임의의 DB에 그대로 실행하면 이 검증과 같은 범위가 되지 않을 수 있습니다. 별도 표기한 변환·스냅샷을 먼저 맞춰야 합니다. 임시 검증 DB는 점검 후 제거했습니다.

검증 통과는 MySQL 실행 성공과 확인한 집계·키·결과값의 일치를 뜻합니다. 모든 과거 출력 바이트, 당시 오류 원인, 분석 해석 전체 또는 운영 품질을 보증하지 않습니다. 기존 과거 실행 시간과 이번 재검증 결과는 구분합니다.
